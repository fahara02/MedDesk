# Filled prescription, demo LPS and PDF

Release: `20260912-demo-lps`, https://medesk.lifeplusbd.tech/#demo.

The owner requested working LPS and PDF downloads, a populated default studio,
and explicitly approved relaxing rules for the personal demo. The previous
sample page exposed a disabled LPS button; this delivery replaces it with a
working file download and adds Open LPS. Fresh workspaces start with the editable
Ayesha Rahman example. Existing drafts and unsaved-work confirmation are retained.
Real New consultations remain blank, without inheriting the fictional prescriber.

The static sample contains a fictional Bangladeshi patient and prescriber, two
medicines, clinical notes, manual observations, advice and follow-up. It has no
actual band/source references. Both published files come from the same fixture.
The PDF is one A4 page with selectable text, 4,244 bytes. The binary LPS demo is
2,312 bytes. These are sizes for this pair, not a general compression benchmark.

Studio Save as LPS exports the current validated fictional prescription including
its rich editor document. Reopening creates a new record, preserving exact field
text. Save as PDF invokes browser printing for the current rendered document;
the separate sample download always contains the fixed sample.

## Format boundary

[DEMO-LPS.md](../DEMO-LPS.md) defines the experimental contract. LPS signature,
HEAD/CORE framing, CRC32C, private profile and non-production flag are implemented.
CORE uses a private deterministic CBOR envelope, **not the normative CORE-SCHEMA
mapping**. Native reader interoperability and signed/authorized issuance remain
unfinished. `nativeLps: false` is retained, with separate `demoLps: true` capability.
No native source, spec, gate or task count changes. The project remains 57/95.
